# 架构与路线图

本文描述服务的分层架构、设计原则、安全模型与后续演进方向,作为理解与扩展本项目的参考。工具契约见 [工具参考](工具参考.md),后续拟新增能力见 [工具迁移清单](工具迁移清单.md)。

## 分层架构

```
server.py        stdio 入口与 FastMCP 组装;按配置决定是否注册分析工具
tools/           显式注册的工具层(data.py 元数据 / analysis.py 分析与成果)
services/        领域服务:矢量与栅格元数据检查、制图
operations.py    分析编排:缓冲区 / 裁剪 / 空间连接,产出任务与成果
storage.py       数据目录加载与受控路径解析(dataset_id -> 实际文件)
workspace.py     任务与成果存储:隔离任务目录、清单、校验和读取
schemas.py       Pydantic 契约模型(输入输出、SourceRef、ArtifactInfo 等)
settings.py      启动时一次性读取的环境配置
```

依赖方向自上而下:工具层调用服务/编排层,编排层调用存储与工作区;导入本包不产生 I/O 或配置读取。

## 设计原则

- **显式注册**:每个工具以装饰器显式声明并附注解(只读/产出成果),不做运行时反射发现。
- **数据与路径隔离**:对外只暴露 `dataset_id`;服务器路径由管理员目录解析,调用方无法注入路径或 URL。
- **有界读取**:元数据流式遍历、设要素与字节上限;超限报错而非返回部分结果,避免不可控资源消耗。
- **结构化契约**:输入输出均为 Pydantic 模型,提供 output schema;错误携带稳定代码,便于客户端处理。
- **成果即资源**:分析产物落盘为隔离任务成果,通过 MCP resource 以真实字节 + SHA256 交付,而非返回服务器路径。
- **CRS 严谨**:不猜测、不隐式重投影;投影/地理坐标系单位分别处理,保证空间语义正确。
- **配置外置且只读**:配置仅来自环境变量,启动时读取一次;不读项目 `config.yaml`/`.env`,不依赖模型凭证。

## 安全模型

- 单操作员、可信管理员维护的数据目录;不提供多用户认证授权。
- 路径解析拒绝 `..`、绝对路径、URL、Windows ADS,并做符号链接与目录包含检查。
- 输入/输出/成果均设大小与要素上限;上限为文件大小约束,非解压或解析内存上限。
- 不修改输入目录;建议输入目录在操作系统层面设为只读。
- 错误对外屏蔽内部细节(`mask_error_details`),日志写 stderr 不写协议 stdout。

已知边界:目录检查不构成完整 GDAL 沙箱;不防御管理员并发替换文件的 TOCTOU;不保证恶意原生格式解析的进程隔离。

## 路线图

当前提供 stdio 传输、元数据检查、有界矢量分析与制图、任务成果闭环。后续方向(均未实现):

- **传输与接入**:Streamable HTTP、上传通道。
- **多用户安全**:认证授权、租户数据边界。
- **资源治理**:进程级硬超时、CPU/内存隔离、并发配额。
- **能力扩展**:按 [工具迁移清单](工具迁移清单.md) 分批引入可组合的空间分析能力(栅格分析、网络分析等)。

新增能力应延续上述设计原则:显式注册、有界读取、结构化契约、成果即资源。
