# 后续工具迁移清单与筛选建议

- 盘点日期：2026-10-29。
- 对象：原项目 `toolbox` 七个模块与当前 `geospatial-mcp` 服务。
- 性质：**源码静态盘点与架构建议，不是新增功能发布，也不是已完成迁移清单。**
- 定位：作为**后续扩展规划**，对应 [架构与路线图](架构与路线图.md) 的"能力扩展"路线；实施时按小阶段独立验收。
- 配套：[机器可读全量清单](工具迁移清单.json)。

## 1. 结论：迁移可组合的空间能力，不是一比一搬运函数

建议把通用服务定位为“数据准备 → 矢量/栅格分析 → 统计 → 制图 → 可下载成果”的GIS基础工具集。Hermes或其他Agent负责任务编排、业务规则和报告；MCP层保持客户端无关，不引入模型凭证或Hermes强依赖。

**133个旧函数不应包装成133个MCP工具。** 按下表分流：能力值得保留不代表当前代码可直接复用，函数存在也不代表算法正确、边界完整或适合不可信输入。

| 分类 | 旧函数数 | 建议 |
|---|---:|---|
| **E：已有核心覆盖** | **5** | 复用现有入口，核对差异，不再重复注册。 |
| **P1：优先迁移** | **20** | 20项优先能力候选；先补成果契约，再分批实施。 |
| **P2：后续增强** | **20** | 通用但不是最小闭环，按真实任务需求后续增加。 |
| **X：专题选装** | **32** | 领域内可复用，做按需启用的专题工具集，不默认全装。 |
| **M：合并复用** | **34** | 并入已有/建议原语、内部辅助或工作流；不是抛弃这些能力。 |
| **N：不进入通用服务** | **22** | 不提供独立通用GIS入口，保留旧代码或交给业务/ML工作流。 |
| **合计** | **133** | 六类互斥，逐项覆盖，无重复归类。 |

从旧入口口径看，除5个已有核心覆盖外还有128个入口需要做去向决策，**不是128个都要新增**。其中40个进入优先/增强候选，32个专题选装，34个合并，22个不进入通用服务。部分合并项依赖后续P2或专题入口，不能误认为现在已经可用。

**最值得先做**：真实重投影与栅格对齐、掩膜/裁剪、矢量筛选与叠加、栅格计算与重分类、矢栅互转、分区统计与点采样、CSV落图与属性连接、栅格和多图层制图。

**不建议独立搬运**：具体灾损/学校覆盖/森林变化规则、通用模型训练评估、普通OLS与属性聚类、重复阈值/差值包装、任意pickle检查、只改GeoJSON的CRS标签等。

## 2. 筛选口径与当前基线

### 2.1 判断标准

1. **跨任务通用性**：更换地区、数据集和业务后，是否仍可直接使用；不以模块名含Spatial/GeoAI就认定必要。
2. **可组合与可复用性**：输出能否作为下个工具输入；是否与现有原语重叠，能否通过有限参数统一。
3. **GIS服务边界**：是否真正依赖空间几何、CRS、栅格网格或空间关系。通用ML也很可复用，但不必进入GIS基础服务。
4. **标准输入输出**：是否能用受管引用和JSON schema表达；结果能否以GPKG、GeoTIFF、CSV、PNG等受管成果交付，而非任意路径或Python对象。
5. **依赖与资源成本**：是否需要额外重依赖、长时间计算、模型注册或专门执行隔离；优先复用当前依赖栈。
6. **可验证性与安全边界**：算法定义、单位、NoData、边界、随机性是否明确；是否依赖eval、pickle、不受控文件读取等。

这是面向当前项目定位的设计判断，没有假设已获得用户调用频次或性能基准，也不使用伪精确评分。“P1”表示需求优先，不表示直接复制实现就能验收。

### 2.2 实际已经提供的工具

默认无 `GEO_WORKSPACE_ROOT` 时仅2个元数据工具；配置工作区后共有9个显式注册工具：

```text
geo_list_datasets
geo_vector_info
geo_raster_info
geo_vector_buffer
geo_vector_clip
geo_spatial_join
geo_render_vector_map
geo_get_task_info
geo_get_artifact_info
```

其中目录、任务、成果管理不等于旧GIS函数迁移；因此不能用“133−9”计算剩余。Hermes若展示额外资源列举/读取工具，也不能据此增加GIS算法数。

| 标为E的旧入口 | 已有入口 | 不应忽略的差异 |
|---|---|---|
| `Data.get_vector_info` | `geo_vector_info` | 当前只检查元数据，不包含全部旧字段统计；只接受dataset_id。 |
| `Data.get_raster_info` | `geo_raster_info` | 当前不扫描像元统计；只接受dataset_id。 |
| `Vector.buffer_vector` | `geo_vector_buffer` | 已有独立的单位、投影和成果契约，不应再包装旧路径接口。 |
| `Vector.create_spatial_join` | `geo_spatial_join` | 仅left/inner及intersects/within/contains，没有nearest。 |
| `Visual.visualize_vector` | `geo_render_vector_map` | 当前单矢量、有限样式、ASCII标题，不等于旧可视化全部功能。 |

`geo_vector_clip` 已有通用裁剪，但 `clip_by_attribute` 是筛选+裁剪，归M而非完整已迁移。实际范围以[工具注册源码](../src/geospatial_mcp/tools/analysis.py)和[元数据工具](../src/geospatial_mcp/tools/data.py)为准。

## 3. P1：建议优先迁移的20项能力

下列名称均为**建议接口名称，尚未实现**。采用统一入口后实际新增工具数量可能减少，例如多图层制图可统一矢量/栅格渲染；不把“9+20”当作已承诺的注册总数。先保持现有9工具兼容，再决定是否新增入口或扩展原契约。

批次T0/T1等是本次工具扩展子路线的建议编号，**不替代原A/B/C阶段，更不表示C2已经完成**。

|---|---|---|---|

| T1 | `geo_raster_align` | `Data.align_raster_to_reference` | 严格核验CRS、transform、shape和像元原点；允许选择保留/裁剪范围。 |
| T1 | `geo_raster_mask` | `Raster.apply_mask_to_raster` | 区分掩膜与crop；栅格/矢量mask分别验收，输出范围、transform和边界像元正确。 |
| T1 | `geo_render_raster_map` | `Visual.visualize_raster` | 客户端获得实际PNG；NoData透明、色标正确、连续/分类数据区分、中文字体可用。 |
| T2a | `geo_raster_polygonize` | `Data.raster_to_polygons` | 合法0类、分类字段、NoData与4/8邻接；限制输出要素数量。 |
| T2a | `geo_raster_calculate` | `Raster.weighted_sum_rasters` | 有限操作枚举；浮点+整数权重不截断，0不是默认NoData；网格和有效掩膜有基准。 |
| T2a | `geo_raster_reclassify` | `Raster.reclassify_raster` | 离散/区间模式、区间端点和重叠规则、未匹配值、dtype溢出与NoData。 |
| T2b | `geo_rasterize` | `Data.rasterize_polygons` | 指定参考网格、字段/常量、覆盖次序与all_touched；核验预期像元。 |

| T2b | `geo_raster_sample` | `Spatial.sample_slope_aspect_at_points` | 任意注册栅格/受管成果的波段采样；投影转换、越界、NoData、最近邻/插值有约定。 |
| T3 | `geo_vector_dissolve` | `Vector.dissolve_polygons` | 分组union与属性聚合一致；重叠面、空组和无效几何策略明确。 |
| T3 | `geo_vector_overlay` | `Vector.overlay_difference` | 先实现difference并验证孔洞/边界；其他operation逐项验收，不自动宣称支持。 |
| T3 | `geo_spatial_aggregate` | `Vector.count_points_in_polygons` | 验证边界点、重叠面、无匹配及重复计数策略；不只执行join后凭行数推断。 |
| T3 | `geo_geometry_metrics` | `Vector.compute_area_sum` | 面积/长度模式与单位显式；逐要素sum和union面积不混用。 |
| T3 | `geo_vector_filter` | `Vector.filter_features_by_expression` | 有限JSON谓词、类型及空值规则、表达式深度限制；拒绝调用、属性访问和代码执行。 |
| T4 | `geo_table_info` | `Data.get_csv_info` | 编码、列类型、空值、前导0标识符与扫描上限；不将整张表放进模型上下文。 |

| T4 | `geo_table_join` | `Data.join_table_to_vector` | 一对一/一对多/多对多规则、重复键和字段冲突；限制连接膨胀。 |

## 4. P2：20项通用增强能力，按需求再迁移

这些不是“没有必要”，而是暂不阻塞最小分析制图闭环。模型先获得少量边界明确的原语，比一次暴露所有重依赖工具更容易维护和验证。

| 旧函数 | 建议入口 | 主要完善点 |
|---|---|---|
| `Data.add_vector_coords` | `geo_vector_coordinates` | 跨任务坐标字段提取；明确点、质心、内部点及输出坐标系语义。 |
| `Data.calculate_vector_field` | `geo_vector_calculate_field` | 字段派生可复用，但必须以有限运算DSL重写gdf.eval及Python eval路径。 |
| `Data.export_vector_to_geojson` | `geo_vector_export` | 按格式枚举统一导出；不为每种格式各建工具，明确坐标约定与精度损失。 |
| `Vector.compute_convex_hull` | `geo_vector_hull` | 通用包络能力；明确全局/分组/逐要素模式、退化点线和空输入。 |
| `Vector.create_hexagonal_grid` | `geo_create_grid` | 采样与聚合常用；统一格网类型和米制尺寸，控制格网数量。 |
| `Vector.generate_quadtree_cells` | `geo_create_adaptive_grid` | 自适应划分可复用；去除固定非空比例逻辑，明确细分准则及终止上限。 |
| `Vector.generate_random_points` | `geo_random_points` | 通用采样；明确随机种子、最小间距、边界及无法满足约束的行为。 |
| `Vector.extract_obstacle_vertices` | `geo_vector_vertices` | 泛化为几何顶点提取；移除障碍物语义，明确孔洞、去重、索引和Z值。 |
| `Vector.flatten_3d_polygons` | `geo_vector_dimension` | 通用2D/3D维度处理；显式声明Z信息丢失，不能伪造高程。 |
| `Raster.compute_slope` | `geo_terrain_derivatives` | 坡度通用但当前梯度间距有误；重写后以解析DEM验证，可合并坡向和局部起伏。 |
| `Raster.compute_nbr` | `geo_spectral_index` | 统一光谱指数入口；明确NIR/SWIR波段、缩放和除零处理。 |
| `Raster.interpolate_points_to_raster` | `geo_interpolate_points` | 通用插值；旧函数只按mask包围盒建网格，需真正边界mask及外推策略。 |
| `Spatial.density_clusters` | `geo_point_clusters` | 空间点聚类可复用；明确投影距离、eps单位、噪声点与样本上限。 |
| `Spatial.local_moran` | `geo_local_moran` | 可复用空间统计；采用可选依赖，明确空间权重、置换、随机种子、孤岛和显著性解释。 |
| `Spatial.compute_kernel_density` | `geo_kernel_density` | 通用密度估计；明确投影、单位、权重、带宽、网格和边界效应。 |
| `Spatial.ordinary_kriging` | `geo_kriging` | 空间插值可复用但依赖及数值门槛较高；验证变差模型、方差、奇异样本和网格上限。 |
| `Spatial.calculate_group_statistics` | `geo_table_aggregate` | 通用分析辅助；有限聚合函数、空值、分组键与输出规模约束。 |
| `Network.densify_paths` | `geo_vector_densify` | 线加密从路网模块提取成通用几何工具，明确米制步长和顶点上限。 |
| `GeoAI.extract_raster_variables` | `geo_raster_stack` | 提取多栅格变量可泛化为标准多波段堆叠；对齐、分块输出，去NPY/PKL中间格式依赖。 |
| `Visual.create_chart` | `geo_render_chart` | GIS分析结果配套图表；有限图型与字段schema，不接收任意绘图代码。 |

P2中的字段计算要等安全DSL；坡度/坡向要先修正数值实现；Local Moran、Kriging等应按可选依赖组织。统一光谱指数首批可覆盖已有NBR/SAVI，NDVI等是未来扩展，不计为本次已盘点旧能力。

## 5. 合并复用：避免一个公式一个MCP工具

M类共34个，下面按合并方向概括；附录逐项列出。**目标入口中有些仍只是建议，归M不是声称已经可调用。**

| 合并方向 | 来源代表 | 建议边界 |
|---|---|---|
| 栅格有限运算 | 加权、差值、阈值、归一化、取负、洼地深度、简化洪水深度 | `geo_raster_calculate` 使用operation枚举；不引入任意Python表达式。两个加权实现先核验权重语义。 |
| 重分类 | `reclassify_raster`、`reclassify_raster_values` | 一个入口的离散映射/区间模式；统一边界、类型和NoData。 |
| 矢栅互转 | `raster_to_polygons`、`convert_mask_to_polygons`；`rasterize_polygons`、`rasterize_vector_labels` | 分别共用polygonize/rasterize，保留类别值和标签映射。 |
| 地形派生量 | 坡度、坡向、ruggedness | 共用经验证的梯度/邻域内核；当前ruggedness应称local_range，不能混为标准TRI。 |
| 光谱指数 | NBR、SAVI | 一个指数枚举入口，共用波段映射、缩放、NoData和除零策略。 |
| 筛选/属性处理 | 按名称筛选设施、按属性裁剪、控制点、服务时间字段、相似性属性连接 | 安全筛选、字段映射、表连接与裁剪组合；专题默认值留Agent工作流。 |
| KDE | 带宽估计、`compute_kernel_density`、`kde_interpolate` | 一个KDE入口的自动带宽、权重、网格和边界选项；不冒充其他插值算法。 |
| 路网操作 | 单点/批量吸附、上下游流长、路径/距离摘要 | 分别合并snap、flow_length方向参数和结果summary；路网与水文仍是不同插件。 |
| 图导出与地图 | 两个nodes/edges图层函数、路网专题地图 | 建议新增统一 `geo_network_export(mode=nodes/edges)`；原两函数已输出GeoJSON，不能以“返回Python对象”为由淘汰。 |
| 业务统计 | 阈值以上面积、候选起终点选择、分组指标图 | 复用栅格/统计、OD排序与route、图表入口；保留最长等选择模式，不能偷换为最短选择。 |

不要以一个巨大 `geo_run(operation, params: dict)` 取代全部工具：只有输入输出与验证边界接近的同类操作才合并，参数应有明确类型、枚举和上限。

## 6. 专题选装与不迁移范围

### 6.1 X类：32个旧入口进入专题候选，不默认全装

| 工具集 | 代表能力 | 启用条件 |
|---|---|---|
| 路网与OD | 建图、边权、吸附、最短路、距离/OD矩阵、服务区、分配、中心性、意愿线 | 真实交通/设施任务；先建立受管graph/table契约、拓扑和方向/单位规则。 |
| 水文地形 | 填洼、流向、累积量、流域、河段、河网分级、流长 | 明确水文需求；统一DEM、流向编码及边界处理，完成小型基准验证。 |
| NetCDF/气候海洋 | 多维元数据、变量导出、剖面、事件持续段统计 | 真实多维数据任务；定义维度、日历、CF坐标识别策略、切片及资源限额。 |
| 3D/可视性 | 视线遮挡 | 明确2.5D/3D场景与高程来源；当前函数存在不代表完整可视域引擎。 |
| OD流空间统计 | local K / global L | 确认统计对象与假设；源码面向OD流，不能命名成未经核验的通用点模式统计。 |
| 空间模型/生态 | 受管模型栅格预测、生境适宜性 | 有可信模型注册、执行隔离、空间验证和模型版本管理；训练与推理解耦。 |

X类函数数不是最终插件工具数；图导出、流长等还会承接M类能力。专题是否放同进程、独立分发或独立MCP服务，留部署设计确定，不在本轮增加依赖。

### 6.2 N类：22个入口不建议作为独立通用GIS工具

- **具体业务结论**：灾损汇总、洪灾成本、森林砍伐比例、人口道路可达比例、学校覆盖。业务字段、阈值、单价与分母规则应在模板/工作流明确，用通用原语组合。
- **纯ML流程**：训练随机森林、调参、准备数据、欠采样、训练测试划分、普通表格预测、AUC/MSE。它们有复用性，但属于模型服务/训练工作流，不因GeoAI命名就进入GIS核心。
- **非空间统计与决策**：普通OLS、属性KMeans、属性相似性搜索、普通时间序列拟合；空间数据提取与这些分析步骤拆开。
- **危险或容易误解的接口**：任意pickle检查；只改GeoJSON CRS标签；把 `sqrt(g*depth)` 称作一般道路速度；把全局Z分级命名成具有空间显著性的热点检验。
- **存储层重复包装**：`save_network_graph` 实际是读取一个GraphML路径再另存，不是接收Python图对象，应由受管成果管理承担。

**N不等于删除旧源码，也不等于这些业务毫无价值。** 真有稳定领域需求时可以设计专题工作流；不能原样包装危险入口或继续保留误导性算法名称。

## 7. 迁移之前必须完善的基础设施和实现

### 7.1 T0：首先补齐成果链路，而不是先加装饰器

当前限制来自实际源码：

1. 扩展**栅格/表格来源契约**：保留dataset_id/artifact_id边界，为每个操作校验数据kind；不接受调用方任意路径/URL。

上述输入上限不能替代硬资源隔离。远程、不可信或多用户部署仍必须完成C2的认证授权、租户边界、进程隔离及相关测试；本轮选工具不绕过这一前置条件。

1. **几何有效性检查与显式修复**：不静默修复；保留修复前后数量、类型和拓扑变化说明。
